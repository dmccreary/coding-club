# Quiz: What Is a Coding Club

Test your understanding of what a coding club is, how it relates to nearby learning contexts, and why sustainability depends on continuous improvement with these review questions.

---

#### 1. Which three traits, taken together, distinguish a coding club from a graded classroom?

<div class="upper-alpha" markdown>
1. Fixed weekly attendance, a required textbook, and a final exam
2. Optional attendance, a project-driven format, and success measured by what a student makes
3. A certified teacher, a state-approved curriculum, and letter grades
4. Competitive team scoring, a season schedule, and tournament brackets
</div>

??? question "Show Answer"
    The correct answer is **B**. A coding club is defined by voluntary attendance, a project-driven rather than lecture-driven format, and success measured by what a student can make rather than by a test score. Option A describes a classroom, not a club. Option C describes formal schooling with grading. Option D describes a competitive robotics team, which is a different, season-long commitment structure.

    **Concept Tested:** Coding Club
    **See:** [Coding Club](../../glossary.md#coding-club)

#### 2. What is club sustainability, as the term is used in this book?

<div class="upper-alpha" markdown>
1. The capacity of a coding club to keep running smoothly through changes in leadership, venue, or volunteer availability
2. The use of environmentally friendly electronic components in club kits
3. A club's ability to attract the maximum number of new students each semester
4. A budget large enough to cover a full year of supplies without fundraising
</div>

??? question "Show Answer"
    The correct answer is **A**. Club sustainability is the capacity of a club to survive the ordinary turbulence of leadership, venue, or volunteer changes rather than collapsing when one person leaves. Option B confuses the term with environmental sustainability, an unrelated meaning. Option C describes growth, not durability. Option D describes financial stability, which is only one contributing factor, not the definition itself.

    **Concept Tested:** Club Sustainability
    **See:** [Club Sustainability](../../glossary.md#club-sustainability)

#### 3. How does the chapter define a maker space?

<div class="upper-alpha" markdown>
1. A weekly meeting exclusively for students learning to code
2. A formal course that teaches algorithms and data structures
3. A program that only operates during the standard school day
4. A shared workshop stocked with tools like 3D printers and soldering irons, open to makers of any age and project
</div>

??? question "Show Answer"
    The correct answer is **D**. A maker space is a shared workshop open to makers of any age working on any project, and it does not require mentors, a recurring schedule, or a code-and-hardware focus the way a coding club does. Option A describes a coding club instead. Option B describes computer science education. Option C describes an after-school program, a different related concept entirely.

    **Concept Tested:** Maker Space
    **See:** [Maker Space](../../glossary.md#maker-space)

#### 4. What is a lessons learned log?

<div class="upper-alpha" markdown>
1. A single mentor's private diary that is never shared with other volunteers
2. A signed attendance sheet collected at the start of every session
3. A running, organized record of patterns across many sessions' post-event notes
4. A list of every student who has ever registered for the club
</div>

??? question "Show Answer"
    The correct answer is **C**. A lessons learned log collects post-event notes across many sessions into a running, organized record, turning scattered anecdotes into evidence of a pattern. Option A misdescribes it as private and unshared, which defeats its purpose as a succession tool. Option B describes an attendance sheet, a different record entirely. Option D describes a roster, not a log of observations.

    **Concept Tested:** Lessons Learned Log
    **See:** [Lessons Learned Log](../../glossary.md#lessons-learned-log)

#### 5. Why does the chapter describe single leader dependency as "invisible while that leader is present"?

<div class="upper-alpha" markdown>
1. Because state licensing rules forbid clubs from having more than one trained mentor
2. Because the leader deliberately hides club records from volunteers to protect their job
3. Because sessions run smoothly and nothing prompts anyone to notice the missing backup knowledge until the leader actually leaves
4. Because students cannot tell the difference between a sustainable club and an unsustainable one
</div>

??? question "Show Answer"
    The correct answer is **C**. The risk is invisible precisely because everything runs fine day to day while the dependent leader is still there, so there is nothing yet to notice; the gap only becomes visible once that person departs. Option A fabricates a licensing rule not mentioned in the text. Option B invents a motive the chapter never states. Option D is irrelevant to why the risk stays hidden from the organizers themselves.

    **Concept Tested:** Single Leader Dependency
    **See:** [Single Leader Dependency](../../glossary.md#single-leader-dependency)

#### 6. How does continuous improvement differ from the two more common patterns the chapter contrasts it with?

<div class="upper-alpha" markdown>
1. It requires hiring a professional consultant to redesign the curriculum once a year
2. It makes small, deliberate adjustments after every session, instead of running things unchanged or overhauling only after a crisis
3. It eliminates the need for any post-event notes since mentors remember details naturally
4. It focuses only on fixing problems that caused a student to quit the club entirely
</div>

??? question "Show Answer"
    The correct answer is **B**. Continuous improvement means making small, deliberate adjustments after every event based on what was actually observed, contrasted with running every session identically forever or waiting for a crisis before making a large disruptive change. Option A invents an outside-consultant requirement not in the text. Option C contradicts the chapter, which relies on post-event notes as the raw material for improvement. Option D narrows the scope to only crisis-level problems, missing the everyday small adjustments described.

    **Concept Tested:** Continuous Improvement
    **See:** [Continuous Improvement](../../glossary.md#continuous-improvement)

Option C wrongly claims exclusivity that the chapter never asserts.

#### 8. A student at a Moving Rainbow session decides she wants purple lights instead of the red pattern the mentor demonstrated, and the mentor helps her find the right color value. Which learning approach does this best illustrate?

<div class="upper-alpha" markdown>
1. Project-based learning, because the session ends with a finished light pattern
2. Peer learning, because another student explained the fix
3. Informal learning, because the student's own curiosity, not the lesson plan, directed what happened next
4. Hands-on learning, because the student physically touched the LED strip
</div>

??? question "Show Answer"
    The correct answer is **C**. The chapter uses this exact example to define informal learning: the student, not the lesson plan, decides what problem to chase next, and the mentor follows that curiosity instead of redirecting to the planned lesson. Option A is plausible but misses that the defining feature here is the shift in direction, not the finished artifact. Option B does not apply since no peer is involved. Option D is present but not the concept the example was written to illustrate.

    **Concept Tested:** Informal Learning
    **See:** [Informal Learning](../../glossary.md#informal-learning)

#### 9. A mentor plans a session around the goal "tonight, every student will walk out with a blinking light pattern they designed." Which learning approach does this planning language demonstrate?

<div class="upper-alpha" markdown>
1. Peer learning
2. Project-based learning
3. Digital literacy
4. Extracurricular learning
</div>

??? question "Show Answer"
    The correct answer is **B**. The chapter's own test for project-based learning is whether you can finish the sentence "tonight, every student will walk out with a ___"; a session organized around producing one tangible artifact fits that definition exactly. Option A requires students teaching each other, which is not described here. Option C is a broader byproduct of building things, not a planning approach. Option D is a category label unrelated to session structure.

    **Concept Tested:** Project Based Learning
    **See:** [Project Based Learning](../../glossary.md#project-based-learning)

#### 10. Library A's club collapsed within a semester of its founder relocating, while Library B's club continued smoothly after its founder stepped back two years later. What best explains the difference?

<div class="upper-alpha" markdown>
1. Library B recruited a co-mentor and documented decisions, building leadership succession before it was needed, while Library A's founder kept everything in her head alone
2. Library B had a larger starting budget than Library A
3. Library B's founder was simply more talented at teaching than Library A's founder
4. Library A met more often each month than Library B, causing volunteer burnout
</div>

??? question "Show Answer"
    The correct answer is **A**. The chapter states both founders were equally skilled; the difference was that Library B's founder wrote decisions down and recruited a co-mentor within three months, building leadership succession, while Library A's single-leader model meant institutional knowledge left with her. Option B introduces a budget difference not mentioned in the chapter. Option C is explicitly ruled out by the text. Option D invents a meeting-frequency cause the chapter never states.

    **Concept Tested:** Leadership Succession
    **See:** [Leadership Succession](../../glossary.md#leadership-succession)
